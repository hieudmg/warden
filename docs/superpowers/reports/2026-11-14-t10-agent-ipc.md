## Implemented boundary

### TLS before any application bytes

- Private wire and credential versions are2. `credentials-v2.json` replaces the
  old unversioned token-only discovery format. It contains only `version`, the
  random32-byte **IPC** `token`, and public DER `certificate`, in one bounded
  strict-schema JSON record. No API credential exists in this task. Unknown
  fields/versions, trailing JSON, bad lengths/certificate/name and records above
 16KiB fail closed. No separate certificate path or key-file loader is added.
- Each runtime generates a fresh standard ECDSA P-256 self-signed identity in
  Go. Its private key stays only in the TLS configuration in memory, never PEM,
  JSON, arguments, environment or logs. NotBefore permits one minute of local
  clock skew; NotAfter is year9999 so there is no periodic renewal/restart/token
  persistence mechanism. The runtime pin/key are replaced on actual restart.
  Standard Go validity checks still apply; expired/future certificate fixtures
  are refused. This is local pinning, not public-CA or zeroization certification.
- Client `Runtime.connect` reads one validated credential snapshot, creates a
  **dedicated** root pool, verifies fixed `warden-agent` name/time and exact leaf,
  and completes TLS before returning the connection *and its matching IPC token*.
  `Runtime.Dial` also authenticates; `tryRuntime` cannot perform the old separate
  token-read/raw-dial sequence. All production request callers use this path.
- Both sides restrict TLS to1.3. No system roots, `InsecureSkipVerify`, plaintext
  fallback, client session cache, tickets/resumption, key logging or early
  application data are enabled. A relaying impostor can forward ciphertext but
  cannot read the request. No bespoke nonce/MAC/encryption proof was invented.
- Server dispatch refuses non-TLS connections and explicitly handshakes before
  reading token-authenticated frames. Existing1MiB frame bounds, token checking,
  wrong-token sanitized final responses, operation error redaction, streams,
  stdin EOF and exit status are retained.
- Dial+handshake is capped at2s (or earlier caller deadline). Initial server TLS,
  first authenticated frame and rejected-token response share a2s deadline; the
  deadline is cleared after a valid request. Overall attach/start/retry is5s,
  including the first attach attempt. After the independent-review P1 correction
  below, client relay teardown closes the owned raw transport before TLS Close
  on every exit, including entry cancellation, local encode failures and final
  responses. Completed payload/final frames are preserved; close-notify delivery
  is not a completion dependency. Cancellation callbacks remain stopped/joined.

### Private discovery, exclusive ownership and crash handling

- Native directory/file validation precedes trust consumption. Unix rejects
  symlink ancestors/final entries, wrong effective-user ownership, unsafe
  directory/socket/file modes and multiply-linked files. Files use descriptor-
  relative `Openat` with `O_NOFOLLOW`, type/owner/mode/link validation, then read
  that descriptor. A private ancestor can protect otherwise writable descendants
  (as with Go's numbered TempDir below its private parent); a writable accessible
  ancestor is not accepted. No chmod/chown of an existing untrusted directory or
  credential file is used as a repair.
- Windows creates explicit protected current-user-only DACLs on new directories,
  credentials and lock files, with the current user as owner. Native relative
  `NtCreateFile` opens under an anchored directory handle and validates type,
  reparse state, link count, owner and DACL on the opened handle before reading.
  Other-principal/inherited/unsupported ACE forms and missing/unprotected/null
  DACLs fail closed. Mode bits are never Windows privacy evidence. Pipe creation
  uses an explicit current-user descriptor, winio's exclusive first instance and
  remote-client rejection; predictable names alone are not trusted.
- A persistent private `runtime.lock` file holds a lifetime nonblocking OS lock
  (`Flock` / `LockFileEx`). The lock, not the file's existence, is ownership.
  A losing starter's `Cleanup` has no rights and cannot delete the winner's
  endpoint or credentials. Normal owner cleanup closes the listener and removes
  discovery while still holding its lock. The harmless lock file remains.
- Startup validates stale discovery, generates identity in memory, and **binds
  before publication**. It creates a private exclusive random sibling, completely
  writes/syncs/closes it, then hard-links exclusively into place. After the P2
  correction below, readiness additionally requires successful staging unlink.
  An unlink error fails startup and preserves both ambiguous links, without a
  deferred retry/repair. Publication never overwrites an unexpected destination
  or exposes partial JSON. File and
  directory operations are anchored; untrusted certificate/key paths are not
  followed. Unsupported private creation or hard-link publication fails closed.
- Existing valid stale discovery is replaced only after winning both the OS lock
  and listener. Unix removal requires an owned private socket, definitive
  ECONNREFUSED, and same inode/type/owner/mode after probing. Timeout/permission/
  inconclusive errors and changed regular-file endpoints are preserved. Windows
  never joins a preexisting squatter's listener.
- A post-Listen subprocess crash is recovered with a new key/certificate/token,
  not reuse of old trust. Prepublication staging alone is not readiness. A crash
  between hard-link publication and staging unlink leaves two links: it is
  deliberately **inconclusive/fail-closed**, preserved for manual inspection,
  not automatically deleted or accepted. Corrupt/unknown/broad/symlink/hardlink
  state likewise needs inspection after verified old-process termination. Old
  token-only files are never used for version2 authentication.

**Security premise:** the public pin is authoritative only while native runtime
filesystem protections hold. Same-user, administrator/kernel or live-process
compromise can replace/read authorized state or steal live material; TLS pinning
is not a solution to those threats. Go reference dropping is best effort, not
proof of GC/crypto-memory erasure. Windows claims require native execution below.

### Same daemon; independent graph lifetime

- Removed `watchPool`'s Used/Empty/EmptySignal listener-close logic. The watcher
  still performs resource expiry, but neither initial empty pool nor all graphs
  expiring ends the process. Production graph idle TTL remains10minutes after
  final release. No timed daemon exit or authentication timer was added.
- External context cancellation closes listener/active IPC transports, cancels
  operations, closes pool-owned cached and retired-active graphs, joins handlers
  and cleans runtime discovery. A small private `Pool.shutdown` termination path
  closes active graphs **before waiting for their borrowers**; tracking retired
  active entries prevents missing them. Normal `Pool.Close`/retirement retains
  its existing lease-safe behavior. Graph ownership and reverse-order Graph.Close
  remain unchanged; this force-close path runs only when the daemon terminates,
  not on a request failure/logout/empty pool.
- The hidden same-binary command uses `signal.NotifyContext` for interrupt and
  SIGTERM and treats clean cancellation as success. Forced process kill/crash is
  not promised graceful cleanup; its OS-lock/stale-state behavior is tested.
- Client cancellation now interrupts a blocked **first** frame write as well as
  later reads, with joined cancellation callbacks and nonblocking reader-result
  teardown. No request or TLS-secret logging was introduced.
- Current agent has zero API credentials: deterministic pool-clock tests advance
  past TTL / years of idle and still connect to the same runtime/pin, then prove
  clean external cancellation with an active IPC connection. T4 logout/revoke/
  outage/restart/lock APIs do not exist yet; their state-specific retention tests
  are explicitly future T4 work, not mocked here and called complete.
- No SSH `forwardAgent`, SSH/proxy/DB dialing, SFTP adapter/transfer or external
  transport code changed. T12's broader unsupported-deadline/channel-open and
  agent-connection lifecycle remediation remains outstanding. Active-graph
  termination closure is the unavoidable minimal lifetime change, not T12.
- **No all-states bounded-shutdown claim:** `Pool.shutdown` skips `e.dialing`;
  chained `via.Dial` and SSH handshake work do not promptly honor context in
  every state. An in-progress graph acquisition can still delay handler joins,
  daemon exit and discovery cleanup. The acquired cached/retired graph tests do
  not cover that state. This known limitation remains deferred T12 work.

### P1 — raw close before TLS Close on every relay exit

Exact Go1.25.14 `crypto/tls/conn.go` confirms that a completed TLS connection's
Close can send close_notify with a **new five-second write deadline**. The old
relay deferred only TLS Close before its entry-context check; later exits also
stopped the cancellation callback before the deferred Close. The loop's explicit
Close calls could likewise bypass raw-first teardown.

RED, before production edits:

```sh
go test ./internal/client/agent -run '^TestRelayRequestClosesRawTLSBeforeCloseNotifyOnEveryExit$' -count=1 -v
```

All four cases failed at the 300ms prompt-return bound: already-cancelled entry,
invalid local JSON, oversized local frame, and received final response. This is a
real completed TLS1.3 handshake over a deliberately nonreading transport, not a
bare first-write net.Pipe test. On failure the fixture force-closes raw I/O and
joins the relay; cleanup releases and joins the TLS peer. Log:
`/tmp/warden-t10-review-p1-red.log`.

Smallest fix: the entry defer now raw-closes before TLS Close on **every** exit;
loop error/cancellation returns use that defer instead of a premature TLS Close.
The callback remains raw-aborting and its stop/join defer is retained. Same
focused command GREEN (`/tmp/warden-t10-review-p1-green.log`). Final strengthened
fixture also requires complete protected stdout plus final-frame delivery and
observes that the raw connection is closed on return; it does not remove TLS,
token authentication, streaming or final-response validation.
