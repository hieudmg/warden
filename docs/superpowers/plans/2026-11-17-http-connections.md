# HTTP connection profiles and server proxy

## Goal and approved boundaries
Deliver web-managed named HTTP profiles and `warden http METHOD NAME PATH [BODY]`, with the Warden server injecting encrypted stored Bearer, X-API-Key, or Basic credentials and returning the upstream response. The profile stores an HTTP/HTTPS origin (scheme, host, optional port), not a path. The request supplies an origin-relative path/query; it cannot change the host. Any configured host is allowed, including loopback/private hosts. Owner explicitly accepts HTTP MITM/credential exposure. HTTPS certificate verification remains mandatory. Do not follow redirects, inherit browser cookies, expose stored secrets in metadata/errors/audit, or introduce application authentication.

Current fetched main is 9610b29 (release 0.24.3). It intentionally uses the documented network-trusted, unauthenticated access model and server-held encryption key. Preserve that model and existing safeguards. Unrelated untracked mise.toml and scripts/ci/ are protected. Initial implementation excluded publication. The owner subsequently authorized fixing the existing SFTP path-spelling regression in this same PR, then committing, pushing, opening a PR and merging it into main after validation. Manual release/tag creation, live application requests and worktrees remain outside scope.
